# Сравнение: наша модель вероятностей и `poe2-crafting-mcp`

Разбор сделан по исходникам [MatthewWinnan/poe2-crafting-mcp](https://github.com/MatthewWinnan/poe2-crafting-mcp)
(клон: `vendor/poe2-crafting-mcp`, 2.1 МБ, Python ~15 тыс. строк + Rust-крейт
`crates/poe2-optimizer`). Запустить его локально не удалось: проект требует Nix
(`flake.nix`, `.envrc`), которого в системе нет. Поэтому ниже — чтение кода и
документации, а не прогон.

## Что это за проект

MCP-сервер для AI-клиентов: импорт билда по PoB-коду, симуляция DPS через движок PoB,
рецепты крафта, проверка цен (poe.show / poe.ninja), сравнение «купить или крафтить».

Ключевые части:

| Часть | Файл | Что делает |
|---|---|---|
| Движок PoB | `poe2_crafting_mcp/engine/pob_engine.py` | встраивает Path of Building через **`lupa` (LuaJIT из Python)**, бутстрап headless, `load_build_from_code` |
| Симулятор крафта | `poe2_crafting_mcp/crafting/simulator.py` | пошаговая симуляция 32 валют + омены |
| Очернение | `poe2_crafting_mcp/crafting/desecration.py` | комбинаторная модель «3 из пула» |
| Своя база модов | `data/poe2_craft.db` (SQLite) | 17 пулов, десятки тысяч записей с весами |
| Оптимизатор | `crates/poe2-optimizer` (Rust) | генетический поиск стратегии (22 валюты — упрощённая модель) |
| Определения валют | `poe2_crafting_mcp/data/currencies.py` | «PoB does not ship currency effect data, so this is maintained here» |

## Их модель вероятностей

1. **Пулы с весами.** Мод описывается `ModSpec` с полями `tier` («1=best»),
   `req_level` («ilvl required to roll this tier») и `weight` («spawn weight
   (DropChance)») — `simulator.py:20-22`. Пул выбирается запросом
   `pdb.get_craftable_mods(item_class, ilvl, pool=...)` — `simulator.py:503` — то есть
   **фильтр по классу предмета и ilvl есть**, как и у нас.
2. **Вероятность цели.** Считают сумму весов префиксов и суффиксов
   (`simulator.py:504-516`: `normal_prefix_weight`, `normal_target_prefix_weight`) и
   берут отношение веса цели к весу пула. В CLI то же самое:
   `total_w = sum(m['weight'] for m in mods)` (`craft_cli.py:802-803`).
3. **Своя база, а не данные PoB.** 17 пулов (`docs/design/optimizer-simulation-fidelity-gap.md:28-48`):
   normal 8 580, desecrated 694, essence 1 935, perfect_essence 516, corrupted 576,
   corruption_upgrade 935, bonded 3 907, socketable 4 971, rune-пулы (chronomancy 102,
   destruction 162, decay 138, marksman 168, berserking 180, soul 147),
   breach_caster 89, breach_minion 74, breach_otherworldly 36. Это **скрейп игровых
   данных**, поддерживаемый автором; PoB таких весов не содержит.
4. **Очернение — комбинаторная модель «3 из пула»** (`desecration.py:191-225, 615-652`):
   `P(hit) = 1 - C(pool - targets, draws) / C(pool, draws)`, где `draws = 3`
   (Колодец Душ предлагает три варианта), а с Abyssal Echoes второй раскрытие
   учитывается как `P(hit) = 1 - P(miss first 3) * P(miss second 3)`.
5. **Омены** (`optimizer-simulation-fidelity-gap.md:57-73`): Sinistral/Dextral
   Exaltation и Annulment, Greater Exaltation (`qty = 2`), Coronation (сторона),
   Whittling (**«approximated»** — «remove lowest-req mod»), Abyssal Echoes (реролл
   раскрытия), Necromancy (сторона на раскрытии), Light (annul бьёт только
   очернённый мод), Catalysing (**«5x at 20% quality»**, в оптимизаторе ещё не
   реализовано), Homogenising — **удалены в 0.4.0**.
6. **Терминальные шаги** (ваал, качество, гнёзда) в оптимизаторе не моделируются:
   `vaal → ✅ (no-op)`, `artificer/armourer/architect → ❌`.

## Наша модель (для сравнения)

* Источник — **только таблицы PoB** (`Data/ModItem.lua`, `ModVeiled.lua`,
  `ModRunes.lua`, `Essence.lua`, `VerisiumCrafts.lua`), извлечённые
  `tools/extract_mods.py`; своих скрейп-баз нет.
* Пул = группы модов, отфильтрованные по **тегам базы, ilvl, открытой стороне,
  `minModLevel` валюты и уже присутствующим группам**; вероятность группы считается
  как доля веса её лучшего достижимого тира в весе пула.
* Гарантированные механики (эссенции, руны) — 100% с указанием мода, тира, уровня и
  лимита; там, где весов в PoB нет (сплавы), панель **прямо пишет, что вероятность не
  выводится**, вместо выдуманного числа.
* Очернение — доля мода в общем пуле по тегу `breach_desecration`; «3 из пула» не
  моделируется.

## Совпадения и различия

| Аспект | `poe2-crafting-mcp` | Наш оверлей |
|---|---|---|
| Источник весов | своя SQLite-база (скрейп) | таблицы PoB |
| Фильтр по классу и ilvl | да | да |
| Взвешенный выбор мода | да | да |
| Учёт сторон (префикс/суффикс) | да | да |
| Очернение | **3 из пула** + echoes (точнее) | доля в пуле (проще) |
| Whittling | «approximated» | **точно**: вычисляем мод с наименьшим уровнем и называем его |
| Сплавы | пул в своей БД, шансы считаются | PoB весов не даёт → «не выводится» |
| Catalysing Exaltation | 5× вес при 20% качества (в оптимизаторе TODO) | помечено как непроверенное, без цифр |
| Homogenising омены | удалены в 0.4.0 | помечены как недоступные в лиге ✓ совпадает |
| Руны | пулы вливаются в общий пул (`--runes`), меняя обычные шансы | сокет руны = гарантированный мод 100% |
| Ваал/качество | терминальные шаги | предмет «locked» (блокер) ✓ сопоставимо |
| Цены | poe.show / poe.ninja, «купить или крафтить» | нет |
| Выход | оптимизация стратегии под цели + MCP для AI | объяснение текущего предмета + шансы, оверлей в игре |

## Что стоит перенять

1. **Очернение как «3 из пула».** У нас есть весь нужный пул из `ModVeiled.lua`,
   поэтому формула `P = 1 - C(pool-1, 3)/C(pool, 3)` (и вариант с echoes
   `1 - P(miss 3)^2`) реализуется без новых данных и делает проценты честнее.
2. **Формулировка «шанс увидеть мод среди предложенных»** вместо «доля в пуле» —
   именно то, что нужно игроку на Колодце Душ.
3. **Идея отдельного пула для сплавов**: у них он есть, у нас — нет. Но брать их
   цифры как истину нельзя (это чужой скрейп), поэтому — либо проверять, либо
   оставить нашу честную пометку.

## Что уже перенято и как это проверено

1. **Модель раскрытия очернения перенесена** в движок (`Item/Mods.revealChance`,
   `Mods.attachReveal`) и показывается в панели рядом с долей мода.
2. **Проверка построчная, а не «на глаз»**: `tools/gen_reveal_reference.py` извлекает их
   функцию `desecration_hit_probability` прямо из их файла (через `ast`, чтобы не тянуть
   зависимости проекта) и прогоняет по сетке пулов; результат — `src/Tests/reveal_reference.lua`
   (76 строк). Тест `test_reveal.lua` требует совпадения **каждой** строки с точностью 1e-9.
   Совпадающие контрольные точки: пул 12 → 25%, пул 8580 → 0.034965%.

## Цены и стоимость верстака: что не удалось взять

* `json/poe2/prices/poec_prices.json` — цены валют в хаосах, но для **своей** лиги
  («Runes of Aldur»), а оверлей настроен на 0.5.5 «Forbidden Rites». Поэтому снимок
  подключается только с ярлыком лиги и вердиктом, а в панели по умолчанию выключен.
* `benchcosts` (3909 записей вида `"2738b1": [{"1": 1}, {"3": 6}]`) расшифровать нельзя:
  ключи — это внутренние id валют Craft of Exile, а карты id → название в их языковых
  файлах нет (там есть `base`, `mod`, `essence`, `fossil`, `catalyst`, но не `currency`).
  Придумывать соответствие мы не стали.

## Их сервер: попытка локального запуска

`poe2-mcp` (не этот проект, а популярный ★82) установлен и продиагностирован: он не
работает с текущими зависимостями (`mcp 2.3.0` — нет `Server.list_tools`; с `mcp 1.2.0`
падает на отсутствующем `greenlet`), а после установки `greenlet` стартует и инициализирует
SQLite, но на `initialize` не отвечает даже за 540 с. Поэтому числовое сравнение сделано
через их чистую функцию (выше) — это надёжнее рукопожатия, потому что проверяет формулу, а
не список инструментов.

Проверено чтением кода и документации, плюс прогон их функции вероятности; полный запуск
`poe2-crafting-mcp` невозможен (нужен Nix).
