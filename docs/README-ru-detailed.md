# PoE2 Craft Overlay

Утилита-оверлей для **Path of Exile 2**, которая помогает крафтить предметы:
по горячей клавише забирает предмет, разбирает его и показывает план крафта в двух
вариантах — **MIN** (минимальный бюджет) и **MAX** (максимальное качество) — с кратким
описанием каждого шага.

Написана на **Lua (LuaJIT x64)** и работает на том же хосте, что и Path of Building:
`SimpleGraphic` + `LuaJIT`, откуда берутся отрисовка, нативный доступ к буферу обмена
и скриншоты. Внешних зависимостей нет: ни Python, ни .NET, ни OCR-движков.

```
F6  захват предмета   →  Ctrl+C игре  →  буфер обмена  →  парсер  →  советник  →  панель
F5  демо-предмет      F7  показать/скрыть панель      F9  кликабельный режим      F10 выход
```

## Что есть в проекте сейчас

Проект вырос из панели в игре в два равноправных способа работы:

| Способ | Как запускается | Для чего |
|---|---|---|
| **Агент + локальный сайт** (альтернативный: требует браузер) | `agent\CaptureAgent.exe` — живёт в трее, значок мухомора | Наводите предмет в игре, жмёте **Ctrl+Q** — страница открывается и обновляется сама, там видны все числа |
| **Панель в игре** (основной) | `run.ps1` (F6/F7/…) | Тот же движок поверх игры, без браузера |

Агент написан на C# (трей и глобальная горячая клавиша требуют нативных вызовов),
движок остался на Lua внутри хоста SimpleGraphic — сайт обращается к нему через тот же
мост, что и MCP-сервер (`mcp/engine.js`).

### Источники данных

| Что | Источник | Как обновляется |
|---|---|---|
| Список лиг | официальный API игры `/api/trade2/data/leagues` | `tools/fetch_leagues.py` → `src/Data/leagues.lua` |
| Цены | **poe.ninja** (PoE2 exchange): вся категория одним запросом | `tools/fetch_prices_ninja.py` → `src/Data/prices.lua`, кэш 30 минут |
| Русские модификаторы | официальные локализованные данные: `ru.pathofexile.com` и `www.pathofexile.com` (одни и те же id) | `tools/fetch_ru_map.py` → `src/Data/ru_stats_*.lua` |
| Русские названия баз | те же списки, выравнивание по сдвигу и согласованности слов | `tools/fetch_ru_map.py` → `src/Data/ru_bases.lua` (3128 пар) |
| Категории предметов | официальный `/api/trade2/data/items` | `tools/fetch_categories.py` → `src/Data/categories.lua` (3129 баз) |

Почему цены не берутся из официального обмена напрямую: `POST /api/trade2/exchange/{league}`
отвергает список валют (`400 Too many items`) и включает лимит после ~5 запросов (`429`),
а poe.ninja отдаёт всю категорию сразу и обновляется примерно раз в час — так же поступают
Sidekick и PoE Overlay.

### Диагностика русского ввода

Русский клиент копирует русский текст, движок построен на английских данных Path of
Building. Перевод идёт по трём источникам (официальная карта → словарь оборотов → словарь
значений), и `analyze_item` возвращает `ruCoverage`: сколько строк закрыто каждым
механизмом и **какие строки остались русскими**. Это измеряет пробелы вместо догадок.

## Быстрый старт

```powershell
cd poe2craft

# 1. Развернуть рантайм PoB2 (копируется из vendor/PathOfBuilding-PoE2, ~28 МБ)
powershell -ExecutionPolicy Bypass -File .\setup.ps1

# 2. Прогнать self-тесты (без графики, на боевом LuaJIT рантайма)
powershell -ExecutionPolicy Bypass -File .\tests.ps1

# 3. Запустить оверлей
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

> Политика выполнения PowerShell в системе может запрещать `.ps1`. Отсюда
> `-ExecutionPolicy Bypass`; файлы скриптов сохранены в UTF-8 **с BOM**, иначе
> Windows PowerShell 5.1 читает их как cp1251 и русские строки ломают парсер.

Если PoB2 лежит в другом месте:

```powershell
.\setup.ps1 -Source 'D:\PathOfBuilding-PoE2'
```

## Панель DSH: `overlay/` + безоконный движок

Основная панель сейчас — приложение на **C#/WinForms + WebView2**, а расчёт остался в Lua:
панель не считает сама, она спрашивает движок и показывает ответ. Движок при этом
**безоконный** — `headless/` собирает `PoE2 Craft Engine.exe` (`WinExe`, ни одного окна),
который грузит `runtime/lua51.dll` и выполняет `src/headless.lua` с тем же файловым
протоколом, что и MCP-мост. Поэтому запуск больше ничего не «мелькает» на экране.

```powershell
cd poe2craft

# ПЕРЕД СБОРКОЙ ЗАКРЫТЬ ПАНЕЛЬ КРЕСТИКОМ: она держит свой exe (MSB3027/MSB3021).
dotnet build overlay\Overlay.csproj -c Release
dotnet build headless\HeadlessEngine.csproj -c Release
dotnet build-server shutdown                      # иначе висят MSBuild/VBCSCompiler
```

Артефакты: `overlay\bin\Release\net8.0-windows\Poe2CraftOverlay.exe` и
`headless\bin\Release\net8.0\PoE2 Craft Engine.exe` (+ рядом `lua51.dll`).
Логи: `overlay\bin\Release\net8.0-windows\overlay.log` и `src\headless_error.txt`.

Запуск — ярлык `PoE2 Craft.lnk` на рабочем столе (создаётся вручную, цель — `Poe2CraftOverlay.exe`).

| Клавиша | Действие |
|---|---|
| **Ctrl+Q** | захват: панель сама отдаёт игре фокус, посылает `Ctrl+C` со **скан-кодами** и читает буфер |
| **× в углу панели** | спрятать панель (движок продолжает жить) |
| **«Выход» в трее** / повторный запуск ярлыка | закрыть и панель, и движок |

### Панели нужны права администратора

**Трей работает только при запуске панели от администратора.** Без повышения прав
`Shell_NotifyIcon` отвечает `error 5` (отказано в доступе), значка в трее нет, а вместе с
ним нет и пункта «Выход» — панель тогда закрывается только повторным запуском ярлыка
(второй экземпляр глушит первый вместе с движком). Поэтому цель ярлыка запускается
с флагом «от имени администратора» (байт 21 в `.lnk` равен `0x60`), и Windows один раз
спрашивает UAC. Заодно это нужно и для того, чтобы `Ctrl+C` доходил до игры: игра
работает с более высоким уровнем целостности, и ключи от непривилегированного процесса
она игнорирует.

Технические подробности, которые стоит знать при доработке:

* **Хоткей — системный.** `RegisterHotKey` (`overlay/Hotkeys.cs`), а не опрос
  `GetAsyncKeyState`: опрос не видит нажатий в окне более высокого уровня целостности.
  Хоткей не перерегистрируется — повторная регистрация того же `Ctrl+Q` возвращала отказ.
* **Фокус возвращается игре** (`overlay/GameFocus.cs`) перед каждым `Ctrl+C`. Без этого
  после перетаскивания или растягивания панели копирование уходило в саму панель, и буфер
  оставался пустым.
* **Пустой захват ничего не стирает**: если в буфере не оказалось предмета, карточка
  остаётся прежней, а не превращается в сообщение об ошибке. Текст удачного захвата
  сохраняется в `src/last_item.txt`, буфер обмена очищается.
* **Гонка чтения запроса** закрыта: движок помечает запрос обработанным только после
  успешного разбора, до 4 повторов; панель ждёт `mcp_serve_response.json` до 20 с.
* **Случайное закрытие отменяется**: `FormClosing` без команды трея переводит панель
  в скрытое состояние (`close cancelled` в логе), движок при этом жив.
* **Запуск — вместе с движком**: панель сразу прогревает движок (запрос `prices`,
  ≈50 мс), индикатор-мухомор на экране ровно эти пять секунд.

Индикатор запуска (`overlay/SplashForm.cs`) — WinForms-форма с прозрачным фоном: сначала
берётся картинка `overlay/Ui/mushroom.png`, а если файла нет или он битый — рисуется
мухомор одним сплошным контуром (`GraphicsPath`, красная шляпка, светлая ножка, лицо).
Откат намеренный: сборка без картинки всё равно показывает индикатор, а не пустоту.
Края сглаживаются, поэтому у окна остаётся тёмный ключ прозрачности (`TransparencyKey`) —
это следующий шаг (слоистое окно, `UpdateLayeredWindow`).

Клавиши ниже относятся к прежней панели, которую рисует сам хост (`run.ps1`), а не к
панели из `overlay/`.

| Клавиша | Действие |
|---|---|
| **F6** | Захватить предмет: оверлей сам отправляет `Ctrl+C` в окно игры и читает буфер обмена |
| **F5** | Разобрать демо-предмет из `samples/rare_gloves.txt` (проверка без игры) |
| **F7** | Показать/скрыть панель |
| **F8** | Очистить результат |
| **F9** | Кликабельный режим (перетащить окно мышью) / вернуть режим оверлея |
| **F1** | Детализация: компактно → обычно → подробно (сворачивает описания и шансы) |
| **F2** | Свернуть/развернуть блок «Предмет» (вместе со строками тиров модов) |
| **F3** | Свернуть/развернуть блок «Планы» (МИН/МАКС) |
| **F4** | Свернуть/развернуть блок «Способы крафта лиги» |
| **Ctrl+F6** | Свернуть/развернуть блок «Заметки» |
| **Ctrl+F9** | Только строки тиров модов |
| **Ctrl+F1 / Ctrl+F2** | Живой предпросмотр: следующий / предыдущий шрифт (панель перерисовывается сразу) |
| **Ctrl+F4 / Ctrl+F5** | Мельче / крупнее текст панели |
| **Ctrl+F7 / Ctrl+F8** | Плотнее / шире межбуквенный интервал |
| **Ctrl+F3** | Сохранить выбранный шрифт, размер и интервал (`src/prefs.lua`) |
| **F11** | Заново применить стиль оверлея |
| **F10** | Выход (завершает процесс) |

### Вид панели: блоки, плотный шрифт, масштаб

**Сворачиваемые блоки.** Панель состоит из четырёх блоков: «Предмет», «Планы»,
«Способы крафта лиги» и «Заметки». У каждого заголовка есть маркер `[-]`
(развёрнут) или `[+]` (свёрнут) и своя клавиша; в кликабельном режиме (**F9**)
заголовок можно свернуть и мышью — под курсором он подсвечивается. Свёрнутый блок
не исчезает: остаётся строка вида `свёрнуто (F4 — развернуть)`, а у блока планов
сохраняется сводка маршрута (`Сфера возвышения -> Божественная сфера`).

**33 каталога глифов на выбор.** `tools/build_fonts.ps1` собирает атласы для моноширинных
Consolas / Cascadia Mono / Cascadia Code / Lucida Console и пропорциональных Segoe UI,
Segoe UI Variable, Segoe UI Semibold, **Verdana**, **Tahoma**, **Calibri**, Trebuchet MS,
Corbel, Candara, Microsoft Sans Serif, Lucida Sans Unicode, Franklin Gothic Medium —
размеры от 11 до 16 px. Все сразу: [font_compare.jpg](docs/font_compare.jpg).

**Межбуквенный интервал (трекинг).** Каждый атлас хранит посимвольную ширину, и к ней
применяется коэффициент сжатия (0.90 для Verdana/Tahoma, 0.94 для остальных). Поэтому
строка идёт плотным блоком, а не разреженной сеткой. Интервал меняется на лету
(`Ctrl+F7/F8`, диапазон 0.80–1.10) и сохраняется вместе со шрифтом.

**Масштаб текста.** Смена шрифта меняет рисунок и чёткость, но не размер: размеры строк
задаются масштабом `ui.textScale` (0.70–1.60, шаг 5%), который меняется по `Ctrl+F4/F5`
и сразу перерисовывает панель. Самый компактный вариант — мелкий атлас (например
`segoe_11` или `verdana_11`) при масштабе 80–90%.

**Свой рендер.** Атласы рисуются через `DrawImage` с текстурными координатами; если
атласа нет, текст автоматически откатывается на `DrawString` с ASCII — оверлей не
ломается, просто теряет кириллицу.

Панель специально сделана компактной, чтобы не закрывать игру:

* **свой жирный плотный шрифт** — атлас собирается из Consolas Bold 16 px, ячейка
  равна межбуквенному интервалу (14×19 вместо прежних 20×26 без «воздуха»), поэтому
  текст читается сплошным блоком, как в панели DSH;
* **сворачивание по клавишам** — `F1` переключает уровень детализации (компактно:
  только названия шагов; обычно: + краткое описание и лучший шанс; подробно: + советы,
  предупреждения и полный список шансов), `F2`/`F3`/`F4` сворачивают отдельные блоки.
  Знамения по умолчанию свёрнуты в одну строку «свёрнуто: … (F3)»;
* **панель по центру экрана** (`overlay.marginCenter`), а не у правого края;
* панель сама подстраивает высоту под содержимое и учитывает, что движок отдаёт под
  отрисовку клиентскую область на ~40 px меньше запрошенной высоты окна
  (`overlay.chromePad`) — иначе подвал с горячими клавишами уходил за край.

Замер: полный набор строк (39 строк, оба плана, шансы) рисуется за 900 кадров ≈ **4.4 с
(~205 кадров/с)**. До кеширования строк тот же прогон не завершался и за 240 с — панель
пересобирала и переразбивала весь текст на каждом кадре.

Хоткеи глобальные: они опрашиваются через `GetAsyncKeyState`, поэтому работают,
пока фокус у игры. Оверлей при этом не забирает фокус (`WS_EX_NOACTIVATE`) и
пропускает клики сквозь себя (`WS_EX_TRANSPARENT`).

### Путь данных

1. **Захват.** PoE2 по `Ctrl+C` кладёт текст предмета в буфер обмена. Оверлей
   посылает это нажатие в окно игры (процесс ищется по имени образа,
   `PathOfExile2.exe`), ждёт `ctrlCDelayMs` и читает буфер через `Paste()`.
   Режим можно отключить (`capture.sendCtrlC = false`) — тогда вы копируете
   предмет сами, а оверлей только читает буфер.
2. **Разбор.** `Item/Parser.lua` разбирает секции (`--------`), свойства, требования,
   гнёзда, имплиситы/эксплиситы, теги `(implicit)`, `(crafted)`, `(enchant)`, `(rune)`,
   диапазоны вида `+(30-40)`, флаги `Corrupted` / `Twice Corrupted` / `Sanctified` /
   `Mirrored` / `Desecrated Prefix|Suffix`. Ключевые слова формата взяты из парсера
   PoB2 (`src/Classes/Item.lua`), чтобы не выдумывать формат.
   Неуверенные случаи не угадываются: они попадают в заметки.
3. **Совет.** `Craft/Advisor.lua` считает число аффиксов и открытых слотов, находит
   первое подходящее правило лиги и собирает два плана со стоимостью (качественная
   оценка: low/medium/high/veryhigh), описанием эффекта и подсказкой.
4. **Отрисовка.** Панель рисуется в левом верхнем углу поверхности; остальное окно
   заливается «цветом-ключом» и становится прозрачным + клики проходят сквозь него.

### Русский интерфейс и собственный рендер текста

Шрифты хоста кириллицу не рисуют вообще: у всех трёх доступных имён (`VAR`,
`VAR BOLD`, `FIXED`) нет кириллических глифов — движок выводит их как
`[u0431][u0432]…`, а имена вроде `Fontin` он отвергает (`invalid option`). Это
проверено скриншотом [font_probe.jpg](docs/font_probe.jpg), а не предположением.

Поэтому у оверлея **свой рендер текста**:

* `tools/make_font_atlas.ps1` растеризует Consolas (ASCII + кириллица + нужные
  символы) в `Data/font_atlas.png` и пишет метрики в `Data/font_atlas.lua`;
* `Core/font.lua` декодирует UTF-8 (в Lua 5.1 нет `utf8`) и рисует каждый глиф
  через `DrawImage` с текстурными координатами;
* если атласа нет, текст автоматически откатывается на `DrawString` с ASCII —
  оверлей не ломается, просто теряет кириллицу.

Проверка: [font_atlas_probe.jpg](docs/font_atlas_probe.jpg) — «Сфера возвышения
(Exalted Orb)», «Предзнаменование истребления (Omen of Whittling)», «Ёжик, ещё,
1234567890 — 45%». Формат «русское (English)» выбран специально: английское
название рядом с русским, чтобы его можно было искать в интернете.

### Проценты выпадения модов

`Data/mods.lua` хранит **веса** модов из PoB, поэтому оверлей считает не «примерно»,
а конкретные доли: для каждого способа крафта строится пул подходящих модов и
нормируется по весам.

Учитывается всё, что влияет на пул:

| Фактор | Как учтён |
|---|---|
| База предмета | точные теги базы из `Data/bases.lua` (`gloves`, `str_dex_armour`, …) |
| Таблица модов | моды фляг/очарований/самоцветов не попадают в пул брони (тег `default` значит «любая база **внутри своей таблицы**») |
| Item level | тиры выше ilvl исключены |
| Сторона аффикса | если префиксы/суффиксы заняты, пул ограничивается свободной стороной |
| Занятые группы | «один мод на группу» — группа, уже висящая на предмете, из пула уходит |
| Greater/Perfect | порог уровня мода 35/50/44/70 сужает пул, но не обнуляет семейство модов |

Пример из панели: у Exalted Orb 183 доступных тира, у Greater Exalted (порог 35) —
101 тир, и рядом с шагом видно проценты: `4.92% Adds (21-24) to (32-37) Cold damage
to Attacks (T1)`. Для шагов-удалений (Chaos/Annulment) показывается шанс снять
конкретный мод (`100 / число модов`).

Актуальная лига — **0.5.5 «Forbidden Rites»** ([официальные патчноуты](https://www.pathofexile.com/forum/view-thread/4000864)).

их подключение к правилам — следующий шаг.

### Данные модов: префиксы, суффиксы и тиры

Клипборд не содержит ни типа аффикса, ни тира — а без них нельзя сказать, что вообще
можно сделать с предметом («все три префикса заняты, значит Exalted добавит только
суффикс»). Эти данные берутся из таблиц PoB2 и конвертируются в Lua один раз на этапе
сборки:

```powershell
python tools\extract_mods.py     # -> src/Data/mods.lua, src/Data/bases.lua
```

Что это даёт:

* **Разделение аффиксов** — «Аффиксы: 1П / 2С, свободно: 2П / 1С», плюс отдельные правила
  для случая «префиксы/суффиксы заняты» (только они решают, что добавит сфера).
* **Тир каждого мода** — определяется **по значению**: `+118 to maximum Life` попадает
  в диапазон `(100-119)` → T6. Если значение не попало ни в один диапазон (например,
  мод из новой лиги), тир считается по item level и помечается `~`, а не выдаётся за факт.
* **Потолок случайного ролла** — по доступным для этой базы группам модов считается,
  какой лучший тир вообще может выпасть на этом item level.
* **Учёт базы** — `Data/bases.lua` даёт точные теги базы (`armour, gloves,
  str_dex_armour, …`), поэтому в статистику не попадают моды самоцветов и фляг; для
  незнакомой базы (новая лига) используется откат на класс предмета.

Честность важнее полноты: если часть модов не опознана, разделение на префиксы/суффиксы
**не выдумывается** — правила по слотам отключаются и выводится заметка. Если распознано
больше суффиксов, чем возможно (значит, строку разобрали неверно), советы по слотам
тоже отключаются. Это проверяется тестами.

Нормализация текста реализована дважды — в Python (сборка данных) и в Lua (рантайм) —
поэтому есть инвариантный тест: нормализация обязана совпасть для **всех** 3056 модов,
иначе тест падает.

## Данные крафта и текущая лига

`src/Data/league_0_5.lua` — это **данные, а не код**. Каждая запись помечена статусом:

| Статус | Значение |
|---|---|
| `core` | устоявшееся поведение валюты PoE2, можно опираться |

## Язык интерфейса

**Панель по умолчанию на русском**, переключается на английский клавишей **F12**
(или параметром `ui.language` в конфиге). Правило именования: русское название, а в
скобках английское — чтобы термин можно было искать в интернете.

```
Редкость: редкий (RARE)            Item Level: 82
Класс: перчатки (Gloves)           Аффиксы: 1П / 2С   свободно: 2П / 1С
T6 +118 к максимуму здоровья (+118 to maximum Life)
T1 +44% к сопротивлению огню (+44% to Fire Resistance)
1) Сфера возвышения (Exalted Orb)  [medium]
   шансы (183 доступных тиров, обе стороны):
   4.92% добавляет (21-24) к (32-37) урона холодом от атак (Adds ... Cold damage to Attacks) (T1)
```

Как это устроено:

* `Core/strings.lua` — все строки интерфейса в двух языках плюс `Strings.name()`
  (формат «русское (English)»), `Strings.term()` (классы, редкость, флаги) и
  `Strings.modName()` (моды);
* `Data/mod_ru.lua` — словарь русских формулировок модов (~60 семейств): числовые
  значения и диапазоны подставляются обратно в шаблон, поэтому
  `+118 to maximum Life` → `+118 к максимуму здоровья`;
* `Data/terms_ru.lua` — термины: классы предметов, редкость, флаги
  (`corrupted` → `осквернён (corrupted)`);
* чего нет в словарях — показывается по-английски: перевод **никогда не выдумывается**,
  а английский оригинал всегда идёт рядом;
* тесты следят, что в обоих языках одинаковый набор ключей, что ключи словаря уже
  нормализованы (иначе поиск не сработал бы) и что английские строки остались ASCII.

По умолчанию панель рисуется **Fontin** — тем самым шрифтом, который использует

* сборщик теперь **сообщает, каких глифов нет** в начертании (`missingGlyphs` в
  метриках и строка «нет глифов: N» в логе). Для Fontin — «все глифы есть», включая
  кириллицу, поэтому русская панель в нём тоже рисуется: [panel_ru_fontin.jpg](docs/panel_ru_fontin.jpg)
  против [panel_en_fontin.jpg](docs/panel_en_fontin.jpg);
* всего в каталоге **40 атласов**: 7 начертаний Fontin плюс прежние варианты; листать
  живьём — `Ctrl+F1`/`Ctrl+F2`, сохранить — `Ctrl+F3`.

### MCP-сервер: движок оверлея для AI-клиентов

Оверлей можно подключить к Claude Desktop, Cursor и любому другому MCP-клиенту:
`node mcp/server.js` поднимает локальный MCP-сервер, который считает **тем же Lua-кодом**,
что рисует панель. Инструменты: `sources`, `analyze_item`, `mod_chances`,
`league_methods`, `runeforging`, `prices` (подробности — [mcp/README.md](mcp/README.md)).

Один вызов = один короткий запуск хоста: мост пишет `src/mcp_request.lua`, хост считает и
пишет `src/mcp_response.json`, мост отдаёт JSON клиенту. Список инструментов мост берёт у
самого движка, поэтому описания не дублируются в JavaScript.

Проверка: `python tools\mcp_e2e.py` (рукопожатие + все инструменты на демо-предмете) и
`python tools\mcp_probe.py -- node mcp\server.js`.

### Очернение: модель раскрытия «3 из пула»

Колодец Душ не выдаёт один мод из пула — он предлагает **три варианта**, поэтому доля мода в
пуле занижает шанс его увидеть. Панель показывает обе величины: долю (8.33%) и раскрытие
(`3 of 12 eligible mods are offered … 25.00% of reveals, 43.75% with Abyssal Echoes`).

Формула — `P = 1 - C(N-targets, 3)/C(N, 3)`, с эхами `P = 1 - miss²`. Это модель сообщества
из `poe2-crafting-mcp`; наш порт (`Mods.revealChance`, `Mods.attachReveal`) проверяется
**построчно** против их кода: `tools/gen_reveal_reference.py` прогоняет их функцию по сетке
пулов и пишет `src/Tests/reveal_reference.lua` (76 строк), а тест `test_reveal.lua`
требует совпадения каждой строки.

### Цены валют (Craft of Exile)

`tools/fetch_prices.py` забирает снимок цен и пишет `src/Data/prices.lua` — вместе с **лигой
и временем снятия**, потому что цена без лиги бессмысленна. Панель показывает цену шага
только если лига снимка совпадает с играемой (`config.ui.pricesLeague`: `nil` — строгое
совпадение, `true` — любая лига, строка — конкретная лига); инструмент MCP `prices` отдаёт
снимок всегда, но с ярлыком лиги и вердиктом. Сейчас снимок относится к лиге Craft of Exile
«Runes of Aldur», поэтому в панели он выключен и печатается причина.

### Механики лиги: что учтено и откуда данные

Панель выводит **процент выпадения мода** для каждого способа крафта. Числа берутся
только из данных, а не из головы: там, где весов нет, панель прямо пишет, что
вероятность не выводится.

| Механика | Источник данных | Что показывает панель |
|---|---|---|
| Сферы (Exalted, Greater/Perfect Exalted, Chaos, Divine, Regal, Annulment, Fracturing и др.) | PoB `Data/ModItem.lua` (веса spawn) + [заметки 0.5.5](https://www.pathofexile.com/forum/view-thread/4000864) | шанс каждого мода из взвешенного пула, с учётом базы, ilvl и открытой стороны |
| Предзнаменования (omens, 20 шт.) | PoB `Data/ModItem.lua` + заметки патча | как знамение меняет операцию и какие шансы получаются (в т.ч. «хотя бы один» для Great Exaltation) |
| Очернение (desecration) | PoB `Data/ModVeiled.lua`, тег `breach_desecration` | пул и проценты по весам (общий пул; конкретная кость может сузить выбор — это указано) |
| Эссенции (Lesser/обычная/Greater/Perfect, 81 шт.) | PoB `Data/Essence.lua` | 100%: какой именно мод даст эссенция для этого класса предмета, с тиром и уровнем мода |
| Руны, сферы душ, идолы, абиссальные глаза (166 шт.) | PoB `Data/ModRunes.lua` | 100%: какой мод даст руна в этот слот, лимит на предмет и требуемый уровень |
| Руносборка (Runeforging / runemastering) | PoB `Data/VerisiumCrafts.lua` | во что превращается база предмета («Runeforged/Runemastered …») |
| Сплавы (Verisium, 13 шт.) | PoB `Data/ModItem.lua` (affix `Verisium` / `of the Stars`), `CurrencyNames.lua` | пул модов сплавов; **шансы не выводятся** — в данных PoB у этих модов вес 0 и нет сопоставления «сплав → мод» |

Раздел `--- Источники данных ---` печатается в панели вместе со способами крафта и
дублируется в текстовую выписку (`last_advice.txt`).
### Русский рендер и выбор шрифта

Шрифты хоста кириллицу не рисуют вообще: у всех трёх доступных имён (`VAR`,
`VAR BOLD`, `FIXED`) нет кириллических глифов — движок выводит их как
`[u0431][u0432]…`, а имена вроде `Fontin` отвергает (`invalid option`). Это
проверено скриншотом [font_probe.jpg](docs/font_probe.jpg), а не предположением.

Поэтому у оверлея **свой рендер текста** со сменными каталогами глифов:

* `tools/build_fonts.ps1` собирает атласы сразу для **11 вариантов** (моноширинные
  Consolas/Lucida/Courier и пропорциональные Segoe UI/Tahoma/Arial) в
  `src/Data/fonts/<id>.png` + `<id>.lua` и пишет манифест `src/Data/fonts.lua`;
* атласы хранят **посимвольную ширину** (`advances`), поэтому пропорциональные
  шрифты идут с правильными интервалами, а не на моноширинной сетке;
* `Core/font.lua` декодирует UTF-8 (в Lua 5.1 нет `utf8`) и рисует каждый глиф через
  `DrawImage` с текстурными координатами; если атласа нет — откат на `DrawString`;
* вариант выбирается в `ui.fontVariant` (`Data/config.lua`), а сравнить все сразу
  можно режимом `src/font_compare.flag` — см. [font_compare.jpg](docs/font_compare.jpg).

* `tests.ps1` — **501 проверка**: парсер, данные модов (нормализация, тиры, базы,

* `src/boot_error.txt` / `src/runtime_error.txt` — ошибки загрузки модулей и кадров
  (любая ошибка Lua пишется в файл, а не «молча висит»).

## Особенности хоста (найденные экспериментально)

Эти факты определяют структуру `Launch.lua`; они проверены на сборке
`SimpleGraphic v2.5-8694a07 x64`:

1. **`RenderInit` обязателен.** Любой запрос рендера (`GetScreenSize`) до него — это
   `Access violation` и падение процесса. Также `RenderInit` отклоняется, если до него
   уже был вывод в консоль (`ConPrintf`).
2. **`Exit()` не завершает процесс.** Он останавливает движок (окно закрывается,
   вызывается `OnExit`), но процесс продолжает жить. Из `OnInit` он вообще игнорируется.
   Поэтому выход сделан через `taskkill` по своему PID (`quitSelf`), а `os.exit`
   в этом хосте также не срабатывает.
3. **Кадровый цикл требует инициализации рендера** — иначе `OnFrame` не вызывается.
   Именно поэтому тестовый режим не полагается на кадры: `tests.ps1` сам закрывает процесс
   по маркеру `test_done.flag`.
4. **Окно принудительно равно размеру поверхности рендера** (`SetWindowPos` переигрывается),
   поэтому «маленькое окно» невозможно — вместо этого используется цвет-ключ
   (`LWA_COLORKEY`) с непрозрачной панелью поверх.
5. **Рабочий каталог скрипта — `src/`**, а не корень проекта: пути в `config.lua`
   (`../samples/...`) считаются от него.
6. **Родной размер окна/поверхности** задаётся `vid_mode`; шрифты при этом
   масштабируются DPI, поэтому шаг строк считается как `(размер + 7) * масштаб`
   (`GetScreenScale`), иначе строки наезжают друг на друга.

## Ограничения и что дальше

* **Захват «с экрана» — через буфер обмена, а не OCR.** Это стандартный подход
  инструментов вроде Awakened PoE Trade: игра сама формирует точный текст предмета,
  поэтому распознавание не нуждается в OCR и не ошибается. Возможность скриншота
  (`TakeScreenshot()`) проверена и доступна, но OCR в рантайме нет — если нужен
  именно OCR-путь, потребуется внешний движок (например, tesseract) и связка с ним.
* **Тиры модов показываются, но без весов.** Тир определяется по значению мода, а
  вероятность конкретного ролла — нет: в данных PoB есть веса (`weightVal`), но
  экономика и приоритеты мод-групп зависят от базы и патча, поэтому «потолок ролла»
  подаётся как доля групп модов, а не как шанс. Добавить взвешенные вероятности можно
  тем же извлекателем (веса уже читаются, но в данные пока не пишутся).
* **Набор правил минимальный и расширяемый**: Normal/Magic/Rare/Unique, осквернённые
  предметы, эссенции, знамения, руны. Дополнительные ветки (конкретные базы, аномалии,
  омены под конкретные слоты) добавляются в `Data/league_*.lua` без кода.
* **Взаимодействие с игрой.** Оверлей только читает текст предмета (одно нажатие
  `Ctrl+C`, как в существующих трейд-помощниках) и ничего не делает за игрока:
  никакой автоматизации геймплея, кликов или перемещений.
* Панель не скроллится: при очень длинном плане список обрезается с пометкой
  `... (list truncated)` (высота ограничена `overlay.maxHeight`).

## Лицензия и происхождение

Рантайм (`SimpleGraphic` + LuaJIT + `Path of Building.exe`) берётся из открытого
проекта **Path of Building Community** (MIT). Ключевые слова формата item-текста
сверены с его парсером `src/Classes/Item.lua`. Сам оверлей — отдельное приложение
и с PoB не связан.

## Проверка панели

Панель — самодостаточный режим: браузер, локальный сайт и порт 17427 не участвуют.
Движок одновременно считает и показывает, поэтому на машине живёт один процесс.

| Клавиша | Что делает |
|---|---|
| **F6** | захват предмета: движок посылает игре `Ctrl+C`, затем читает буфер |
| **F5** | демо-предмет из `samples\` — панель можно проверить, не заходя в игру |
| **F7** | показать или скрыть панель |
| **F8** | очистить результат (пустая панель показывает подсказки) |
| **F1** | уровень детализации: кратко → обычно → подробно (шансы модов) |
| **F9** | кликабельный режим для перетаскивания, обратно — оверлей |
| **F10** | выход |

Захват устойчив к неожиданному вводу: ошибка разбора или нажатия выводится **строкой
статуса в панели**, а не закрывает окно.

### Настройки панели (`src/Data/config.lua`, блок `overlay`)

| Параметр | Смысл |
|---|---|
| `alpha = 255` | непрозрачность: 255 — сплошная панель, 204 — 80 %, 230 — 90 % |
| `clickThrough = true` | клики проходят сквозь панель, игра не теряет управление |
| `topmost = true` | панель всегда поверх игры |
| `width = 700`, `height = 520` | размер; высота подстраивается под содержимое |
| `enabled = true` | режим панели включён |

### Безоконная самопроверка

Полный путь захвата можно прогнать без игры и без буфера:

```powershell
New-Item -ItemType File -Force src\capture_check.flag | Out-Null
.\runtime\Path{space}of{space}Building-PoE2.exe
# результат: src\capture_check.txt — предмет, свойства, моды, планы и цены
Remove-Item src\capture_check.flag
```

Режим проверяет разбор образца, чтение буфера, отрисовку, планы с ценами и выживание
на мусорном предмете — то есть всё, что делает F6, кроме присутствия игрока за игрой.
